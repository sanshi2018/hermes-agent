### 0. 设定 AI 助手的全局人设（最先发送）

在开始提问前，先给你的 AI 工具设定一个基调，防止它陷入低效的代码逐行翻译。

**你可以直接复制这段话发给它：**

> “在接下来的对话中，请你扮演一位拥有 10 年经验的顶级系统架构师。我正在通过阅读源码来系统学习当前工作区内的 Hermes Agent 项目。我的目标是理解其顶层设计思路、解决的核心痛点以及架构演进的必然性。 **核心要求：** > 1. 减少逐行解释代码。 2. 多从数据流向、状态机转换、模块解耦的角度来回答。 3. 请大量使用 Mermaid语法绘制架构图、时序图或状态图辅助讲解。 4. 每次分析请结合具体的模块文件路径（例如 `src/core/loop.py`），让我知道你去哪里找的依据。”

### 1. 第一阶段：宏观架构与设计哲学探究

**Prompt：**

> “请全局扫描整个 Hermes Agent 项目（重点关注根目录结构、核心抽象类和配置文件）。 基于扫描结果，请帮我生成《Hermes 宏观架构设计分析报告》。报告需包含以下内容：
> 
> 1. **核心痛点解决：** 相比于传统的静态图编排框架（如 LangChain），这个项目在系统架构上做出了哪些取舍？它主要解决的 AI Agent 开发痛点是什么？
>     
> 2. **核心模块划分：** 请帮我梳理项目最核心的 4-5 个子模块（如网关、控制循环、记忆、执行器等），并说明它们之间的依赖关系。
>     
> 3. **架构图：** 请用 Mermaid 语法画一张整体的系统架构图（System Architecture Diagram），展示用户的输入是如何流经各个模块并最终产生外部影响的。”
> 4. **🛠️ 动手实操**（如该模块可实操，必须包含）：
    - **最小可运行示例**：脱离原项目复杂度，给出独立可跑的代码，复现该模块核心机制
    - **改造练习**：1-2 个动手改造题（如替换工具、加一个新节点、改 prompt 看输出差异）
    - **预期输出 & 验证方式**：我怎么知道我做对了
> 额外约束 1.以md的形式生成到 devDocs/ 中; 2. 文档不少于5篇，内容应该详实，符合逻辑，易懂
>     

### 2. 第二阶段：核心控制循环与大模型交互流

**Prompt：**

> “请深入分析 Hermes Agent 的核心执行循环模块（通常包含 `loop`、`agent` 或 `engine` 等关键字的源码文件）。 这是系统的大脑。请帮我解答以下设计问题：
> 
> 1. **Prompt 动态编译：** 系统在每次调用 LLM 之前，是如何将环境状态、可用工具、记忆上下文动态拼接成最终的 System Prompt 的？使用了什么设计模式？
>     
> 2. **状态机与流转逻辑：** 在一个包含多次工具调用和重试的复杂任务中（例如 ReAct 范式），系统是如何管理内部状态的？它在什么条件下判定任务成功、失败或需要重试？
>     
> 3. **时序图：** 请用 Mermaid 语法画一张时序图（Sequence Diagram），展示在一个典型的复杂任务中，Agent Loop 与 LLM、Tool/MCP 之间的完整交互过程，重点体现‘错误捕获与自愈（Self-healing）’的环节。”
>     

### 3. 第三阶段：标准化的外部工具集成 (MCP)

**Prompt：**

> “请扫描项目中与工具调用、协议解析相关的目录（重点关注 MCP - Model Context Protocol 的实现细节）。 请帮我分析 Hermes 是如何做到与具体工具解耦的：
> 
> 1. **协议实现：** 系统底层是如何通过 stdio 或 SSE 与外部 MCP Server 建立连接并通信的？它是如何将 MCP 的 Schema 转换为 LLM 能够理解的 `tool_calls` 格式的？
>     
> 2. **痛点对比：** 相比于在代码里硬编码各种 API Client，使用这种统一的外壳协议（Harness Protocol）带来了哪些工程上的决定性优势？
>     
> 3. **扩展指南：** 如果我想自己写一个极简的本地天气查询 MCP 工具接入它，从代码设计层面看，数据流向是怎样的？”
>     

### 4. 第四阶段：记忆引擎与自我进化机制

**Prompt：**

> “请深入分析系统中的长期记忆、用户建模以及技能学习模块（重点关注涉及 SQLite 数据库交互、FTS5 以及 `.skill` 文件生成的代码逻辑）。
> 
> 1. **记忆引擎的底层设计：** 系统是如何利用 SQLite 的 FTS5（全文检索）来管理和快速召回记忆的？请给出核心的数据库表结构（Schema）设计意图。
>     
> 2. **闭环学习机制 (Skill Extraction)：** 当一个复杂任务执行成功后，系统是如何触发‘反思 (Reflection)’并固化成 Markdown 技能文件的？请找出执行这一步的底层系统 Prompt 设计，并分析它为什么这么写。
>     
> 3. **上下文管理痛点：** 它是如何解决长期对话导致大模型 Token 溢出或‘注意力涣散’问题的？（分析其摘要或截断机制）。”
>     

### 5. 第五阶段：安全执行面与沙盒边界

**Prompt：**

> “最后，请分析项目的执行层（Execution Surfaces，可能包含 Docker、Shell、远程 SSH 等关键字的实现）。
> 
> 1. **物理隔离层设计：** 当模型决定运行一段可能有破坏性的 Shell 脚本时，Harness 层是如何拦截并将其放入沙盒环境中的？
>     
> 2. **I/O 接管：** 它是如何实时接管沙盒内的 `stdout` 和 `stderr`，并在遇到崩溃时自动构建反馈环（Feedback loop）让大模型进行自我修复的？
>     
> 3. **状态图：** 请用 Mermaid 语法画一张状态图（State Diagram），展示一段代码从‘大模型生成’到‘环境准备’、‘执行’、‘捕获报错’、‘重试’直到‘成功提取技能’的完整生命周期。”
>
